# زُهي | ZUHI — GitHub + Supabase

نسخة كاملة من واجهة زُهي مرتبطة بـ Supabase بدل localStorage.

## ماذا تم حلّه؟
- المنتجات لا تختفي بعد Refresh لأن مصدرها قاعدة بيانات.
- المنتجات المضافة من لوحة الإدارة تظهر لكل الزوار من أي جهاز.
- كل منتج لديه `affiliate_url`، وزر **شراء الآن ↗** يفتح صفحة المنتج الخارجية مباشرة.
- كل منتج مربوط بدولة (مصر / الإمارات / السعودية) وتبويبات فوق قسم المنتجات للتصفية حسب الدولة.
- قسم "آراء العملاء" و"تواصل معنا" بشكل أكورديون (بطاقة صغيرة تتوسع بضغطة سهم).
- رسائل نموذج التواصل تُخزَّن في جدول `messages` وتظهر للأدمن فقط في تبويب "الرسائل".
- لوحة إدارة حقيقية عبر Supabase Auth، فيها تحكم كامل: منتجات، أقسام، خدمات، آراء عملاء، رسائل، وإعدادات الموقع (اسم الموقع، صورة الغلاف، صورة قسم "من نحن"، بيانات التواصل).
- صلاحيات RLS تمنع الزوار من تعديل أي جدول؛ فقط القراءة العامة للمحتوى الفعّال.
- رفع صور المنتجات وصور الموقع (الغلاف/من نحن) إلى Supabase Storage.
- التحكم في اللوجو من الإعدادات؛ إذا تُرك فارغًا يستخدم صورة النبذة تلقائيًا، ويظهر نفس الشعار في الهيدر والفوتر ولوحة الإدارة.
- تحديث فوري للموقع عبر Supabase Realtime عند تعديل المنتجات أو الأقسام أو الخدمات أو التقييمات أو إعدادات الهوية.
- زر تثبيت كتطبيق PWA على المتصفحات الداعمة، مع manifest وservice worker.
- ملف SQL يضيف 60 تقييمًا تجريبيًا مختلفًا بتقييم 4 أو 5 نجوم دون تكرار.
- زر المشاركة يفتح اختيارًا واضحًا لمشاركة الرابط أو نسخه، وآراء العملاء تتبدل تلقائيًا أثناء العرض.
- يمكن تعديل نصوص الواجهة الرئيسية وقسم "من نحن" بالكامل من تبويب الإعدادات في لوحة الإدارة.
- يمكن تشغيل لوحة الإدارة بوضع محلي بدون بريد عبر `LOCAL_ADMIN_MODE` و`LOCAL_ADMIN_PASSWORD`؛ التعديلات المحلية محفوظة في نفس المتصفح فقط.
- تم حذف السلة نهائياً — الشراء يتم مباشرة برابط العمولة.
- Responsive + RTL + موجة نيون خضراء متحركة شفافة في الخلفية + Hover نيون أخضر على البطاقات.

> **مهم:** إذا كان عندك مشروع Supabase شغّال بالفعل من نسخة سابقة، فقط افتح SQL Editor والصق `supabase.sql` كامل مرة أخرى — الأعمدة والجداول الجديدة (`country`, `testimonials`, `messages`, `site_settings`, وأحدث إضافة `images` و`attachment_url`) هتتضاف تلقائياً من غير ما تفقد بياناتك الحالية.

## آخر تعديلات (هذه النسخة)
- **صور متعددة للمنتج:** من لوحة الإدارة تقدر ترفع أكتر من صورة للمنتج الواحد (أو تلصق روابط صور بفاصلة)، وعند العميل بيظهر سهمين يمين وشمال (وسلايدر نقط تحت الصورة) في نافذة "الوصف والتفاصيل" للتنقل بين الصور. **لازم تشغّل `supabase.sql` تاني عشان يضيف عمود `images` الجديد لجدول `products`.**
- **إصلاح آراء العملاء:** الرأي المفتوح بقى ياخد الصف كامل بدل ما نصه يظهر متداخل تحت رأي تاني.
- **الناف بار متجاوب أكتر:** ارتفاع الهيدر واللوجو والأزرار بيصغروا فعليًا على شاشات الموبايل بدل ما يفضلوا بنفس المقاس.
- **نافذة مشاركة بعد 13 ثانية:** تظهر تلقائيًا للزائر بعد 13 ثانية من دخول الموقع، بتشجعه يشارك زُهي مع غيره مقابل كوبون خصم (رسالة تشجيعية فقط، مفيش نظام أكواد خصم حقيقي مربوط بيها).
- **إرفاق صورة في "تواصل معنا":** زر ＋ جنب مربع الرسالة يسمح للعميل يرفق صورة مع رسالته، وتظهر الصورة للأدمن في تبويب "الرسائل". **محتاج bucket جديد اسمه `message-attachments`، بيتضاف تلقائيًا من `supabase.sql`.**
- **تاجر مع زُهي:** رابط جديد أسفل الهيدر يفتح نموذج (العنوان، محتويات القائمة، رقم الهاتف، البريد الإلكتروني، اسم المنتج، صورة المنتج، سعر المنتج)، وزر الإرسال بيفتح واتساب مباشرة برقم `whatsapp` المسجل في إعدادات الموقع، مع كل بيانات الطلب (ورابط صورة المنتج لو اتضافت). **محتاج bucket جديد اسمه `merchant-images`، بيتضاف تلقائيًا من `supabase.sql`.**

## 1) إنشاء مشروع Supabase
أنشئ مشروعاً على Supabase ثم افتح SQL Editor والصق محتوى `supabase.sql` بالكامل.

بعد ذلك من Authentication > Users أنشئ مستخدم Admin بالبريد وكلمة مرور قوية.
انسخ UUID الخاص بالمستخدم وشغّل في SQL Editor:

```sql
insert into public.admin_profiles(user_id) values ('UUID_OF_YOUR_ADMIN_USER');
```

## 2) إعداد المفتاح للواجهة
انسخ:

`config.example.js` → `config.js`

ثم ضع:

```js
window.ZUHI_CONFIG = {
  SUPABASE_URL: 'https://YOUR-PROJECT.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR_ANON_OR_PUBLISHABLE_KEY'
};
```

المفتاح المطلوب هنا هو anon/publishable key فقط. **لا تضع service_role key داخل GitHub.**

## 3) تشغيل الموقع
يمكن فتح `index.html` عبر استضافة Static، أو نشر المجلد على GitHub Pages.

لو كنت تستخدم GitHub Pages:
- ارفع كل الملفات إلى repository.
- فعّل Pages من Settings > Pages.
- اترك `config.js` في المشروع فقط إذا كان يحتوي على anon/publishable key.

## 4) لوحة الإدارة
الرابط:

`/admin/`

في الوضع الافتراضي تستخدم البريد وكلمة المرور من Supabase Auth. وللاستخدام المحلي بدون بريد، غيّر `config.js` إلى `LOCAL_ADMIN_MODE: true` وحدد رمزًا خاصًا في `LOCAL_ADMIN_PASSWORD`.

> الوضع المحلي مناسب للإدارة من جهاز واحد فقط. لا تضع فيه بيانات حساسة، ولا تتوقع أن تظهر تعديلاته على أجهزة الزوار الأخرى؛ للتزامن العام استخدم وضع Supabase Auth.

منها تستطيع:
- إضافة/تعديل/حذف المنتجات.
- رفع صورة المنتج.
- وضع رابط العمولة الخارجي.
- إظهار/إخفاء المنتج.
- إدارة الأقسام.
- إدارة الخدمات.

## 5) روابط العمولة
في خانة رابط الشراء ضع رابط العمولة الكامل، مثال:

`https://www.example.com/product/123?affiliate_id=YOUR_ID`

العميل لا يظل داخل زُهي عند الضغط على شراء؛ يتم فتح الرابط الخارجي مباشرة.

## 6) مهم قبل النشر
- استخدم كلمة مرور قوية جداً للـAdmin.
- إذا نسيت كلمة السر، اكتب بريد الأدمن في صفحة `/admin/` واضغط "إرسال رابط تغيير كلمة السر". لا يمكن قراءة كلمة السر الحالية من النظام.
- **إذا كانت كلمة مرور الأدمن الحالية اتبعتت كنص عادي في أي محادثة (شات) من قبل، غيّرها فوراً** من Supabase → Authentication → Users → اختر المستخدم → Reset Password.
- لا تضع service_role key في `config.js`.
- لا تشارك حساب Supabase Admin.
- رابط `/admin/` أصبح يظهر في الفوتر كأيقونة ترس ⚙ صغيرة وشفافة بدل كلمة "إدارة" — هذا تمويه بسيط فقط وليس حماية حقيقية؛ الحماية الفعلية هي تسجيل الدخول عبر Supabase Auth + صلاحيات RLS.
- راجع شروط برنامج Affiliate الذي تستخدمه، خصوصاً سياسة الروابط وطرق التتبع.
